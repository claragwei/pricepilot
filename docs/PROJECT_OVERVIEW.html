PricePilot: project overview

Explainable pricing decision support on real retail scanner data. Status as of 2026-11-02.

Why it is built this way

  • Raw files stay untouched and checksummed, so every number traces back to the source.
  • dbt tests and a rejects table make bad data fail the build, not slip through quietly.
  • Backtests split by time, never at random, so future weeks never train a model scored on the past.
  • A simulator with a known true price sensitivity is the only way to tell whether a policy or an elasticity estimate is right, so its results are always labeled simulated.

How we checked it (real results so far)

  • Loader: 56 tables, 175,521,485 movement rows, each matching an independent gzip -dc | wc -l line count.
  • dbt: dbt build gave PASS=22 WARN=1 ERROR=0 on cereal and tissues.
  • Not built yet, no results claimed: forecaster results, simulator, DDPG, MLOps, API, app, RAG, dashboard.
