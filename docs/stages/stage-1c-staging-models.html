Slice 1c: staging models (cleaning)

Apply the approved cleaning rules in dbt to every category, and test them.

What we did

Why

  • OK = 0: the manual calls it "trash" and the source authors exclude it.
  • No sale recorded: among OK = 1 rows, price > 0 and MOVE > 0 match exactly, so a zero price means no sale. Weeks are not filled in.
  • Rejects table, not deletion: counts reconcile and rules can be audited.
  • Nulls, no imputation: a made-up price or margin would look like real data.
  • Views: disk was at 20 GB free and tables would take about 15 GB.

How we checked it

  • uv run dbt build --project-dir dbt --profiles-dir dbt: PASS=20 WARN=1 ERROR=1 (441 s). *The error was the UPC link test; it now warns (decision 57).
  • Found: 1,259 blank rows (now incomplete_row) and 77,498 rows with a UPC absent from the source product files.
  • Independent counts on each raw table equal the clean views, category by category.
  • Warning: promo codes G, L, M, N occur; the manual lists only B, C and S.
  • Open: Snowflake run not done, reject-share limits are first guesses.
